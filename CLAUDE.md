# Dotfiles

Max's dotfiles for macOS and Coder Linux boxes. Managed by **mise**; terminal workspaces by **Herdr**.
The repo root mirrors `~`. Read a tool's docs before changing its config; do not guess option names.

The README holds the operational how-to (daily commands, adding things, where to look when
something is off); this file holds the design and the gotchas. Both load together:

@README.md

## How it fits together

Two mise config files with different jobs:

- `mise.toml` (repo root) is the **bootstrap project**. It declares the dotfile links, the zsh
  plugin clones (`[bootstrap.repos]`), the Homebrew casks and formulae mise pours itself
  (`[bootstrap.packages]`), and a `bootstrap` task that writes shell completions to `~/.zfunc`.
  Run it from the repo directory: `mise trust && mise bootstrap`, or `./install.sh`.
- `.config/mise/config.toml` is the **global config**: every tool and mise setting that applies
  everywhere. The bootstrap links it to `~/.config/mise/config.toml`, so `mise use -g` edits the
  repo file. Every tool is declared as `latest` and there is deliberately **no lockfile**: each
  machine gets whatever `latest` is when it runs `mise install` or `mise up` (see Things to know).

Dotfiles are linked by mise, not Stow. `[dotfiles]` in `mise.toml` has three `symlink-each` entries
(`~/.config`, `~/.local/share/navi/cheats`, `~/scripts`: real directories at the target, one link
per **git-tracked** file, untracked files ignored) plus one `symlink` entry per home-level file
(`.zshenv`, `.zprofile`, `.zshrc`, `.zsh_path.zsh`, `.p10k.zsh`, `.gitconfig`) and one `copy`
entry for `.linear/coding-tools.json`, which Linear rewrites.

Machine-local and never tracked: `~/.localenv` (sourced by `.zshenv`, e.g. `NODE_AUTH_TOKEN`),
`~/.localrc` (sourced by `.zshrc`), `~/.npmrc`, everything under `~/.claude/`, and Herdr's runtime
files in `~/.config/herdr/` (socket, logs, `session.json`). The repo's own `.claude/` directory is
Claude Code's project state and is gitignored.

## Tools

Docs links and the help commands for every tool are in the README: mise and Herdr under their own
sections, everything else under "Tool docs and help".

- **mise** — tools, env, machine bootstrap, dotfiles. Installed from `mise.run` to
  `~/.local/bin/mise`. Commands and help: see the README.
- **Herdr** — terminal workspace manager. Config `.config/herdr/config.toml` (defaults plus: an
  Everforest theme as `[theme.custom]` overrides, toasts via the terminal, worktrees under
  `~/code`, battery and clock in the tab bar, and prefix-free `ctrl`/`alt` chords for the daily
  actions, kept alongside the `ctrl+b` defaults). Commands and help: see the README. Cheat:
  `navi` → herdr.
- **zsh** — `.zsh_path.zsh` builds PATH and is sourced by both `.zshenv` and `.zprofile`;
  `.zshrc` is interactive-only setup. Plugins are plain clones under
  `~/.local/share/zsh/plugins/`, sourced in this order: powerlevel10k (theme), fzf-tab (after
  `compinit`), zsh-autosuggestions, zsh-syntax-highlighting (last plugin), then zoxide last of all.
- **Powerlevel10k** — `.p10k.zsh`, generated by `p10k configure`; self-documenting.
- **Ghostty** — `.config/ghostty/config.ghostty` (that filename is Ghostty's canonical one).
- **Helix** — `.config/helix/`. `space e` opens yazi as a file chooser inside Helix.
- **yazi** — `.config/yazi/`; its keymap calls the four scripts in `scripts/yazi/`.
- **navi** — `.config/navi/config.yaml`, cheats in `.local/share/navi/cheats/`. Installed as a
  `brew:` formula because upstream ships no macOS build.
- **revdiff** — `.config/revdiff/` (config, keybindings, the `everforest` theme). revdiff writes its
  bundled themes and `history/` into that directory at runtime, which `symlink-each` tolerates.
- **difftastic** — git's external diff via `.gitconfig`; `lg` and `shw` aliases re-enable it for
  `log -p` and `show`. Opt out per command with `--no-ext-diff`.
- **git** — `.gitconfig`; global excludes in `.config/git/ignore` (`*.local`, `*.local.*`).
- **OpenCode** — `.config/opencode/`, carried over as-is.
- **Scripts** (`scripts/`): `battery/battery-status` (plain text for Herdr's tab bar),
  `claude/statusline.sh` (Claude Code status line; wired by the machine-local
  `~/.claude/settings.json`), `helix/hx-open` (dev servers' "open in editor" → Helix in a new Herdr
  tab; `.zshrc` exports it as `LAUNCH_EDITOR`), `linear/linear-work` (Linear "Work on issue" →
  Herdr worktree workspace with Claude started on the ticket), `herdr/worktree-remove` (fzf
  multi-select removal of worktrees across `~/code`, opened as a Herdr popup by Ctrl+Shift+d;
  renames each checkout aside and deletes it in the background because a mono checkout takes
  ~20 s to rm; never deletes branches), `yazi/*`.

## Things to know

- **`symlink-each` targets are narrow on purpose.** The first apply of a `symlink-each` entry walks
  its entire target directory looking for old links to prune (mise discussion #11548; the saved
  state added in PR #11549 only exists after that first apply). Targeting `~` crawled all of
  `$HOME` for over 30 minutes here. Keep targets to directories this repo populates.
- **Only git-tracked files get linked.** `manifest = "git"` means a new file is invisible to
  `mise dot apply` until `git add`. Deleting or excluding a tracked file removes its link.
- **PATH follows mise's model.** `.zshenv` puts `~/.local/share/mise/shims` on PATH statically (no
  fork) so scripts and agent shells see tools; `.zshrc` runs `mise activate zsh`, which swaps shims
  for real tool paths at every prompt. `.zprofile` re-sources the PATH file because macOS
  `/etc/zprofile` runs `path_helper` after `.zshenv` and reorders PATH; Herdr starts login shells,
  so every pane passes through it. Herdr's own custom-command keybinds never see the zsh files:
  `type = "shell"` runs via `/bin/sh -lc` (reads `~/.profile`), `pane` and `popup` via a
  non-login `/bin/sh -c` from the focused pane's directory, so scripts they launch set PATH
  themselves.
- **Aliases and zoxide are interactive-only.** Claude Code's Bash tool sources a non-interactive
  snapshot of `.zshrc`; unguarded aliases (`ls` → `eza`) break tools there, and zoxide's `cd` would
  record every agent directory change.
- **Project pins beat global versions.** `idiomatic_version_file_enable_tools` makes mise honour
  `.nvmrc`, `.node-version`, `.tool-versions`, `.python-version`, and `package.json`
  `packageManager` (with its `+sha` checksum). Global `node`, `pnpm`, `yarn` are only fallbacks.
  This replaces both fnm and Corepack.
- **Python**: `uv` is the tool; `python.uv_venv_auto = "source"` activates a uv project's `.venv`
  when entering it (needs `uv.lock`; needs `mise activate`, not shims).
- **No lockfile, on purpose.** `lockfile = true` was tried and dropped: with the global config
  linked from this repo, an explicit `mise install` run inside a work repo that pins a globally
  declared tool through `package.json` (rosetta's `pnpm`) rewrote the global lock entry for that
  tool every time, turning a committed file into churn. mise's default (no lockfile) avoids the
  whole class: `mise up` updates in place and nothing needs committing.
- **Backends**: `ubi:` is deprecated in mise; use `github:owner/repo` (revdiff does).
- **mise inside Claude Code's sandboxed Bash tool.** Any mise command that needs the network
  (installs, version resolution, `mise up`) fails there with TLS certificate errors from the
  sandbox proxy. That is the sandbox, not mise; run those commands with the sandbox disabled.
- **Herdr's Claude integration is machine-local.** `herdr integration install claude` writes
  `~/.claude/hooks/herdr-agent-state.sh` and a `SessionStart` hook into `~/.claude/settings.json`.
  It reports the session id for `claude --resume` after a Herdr restart; Claude's working/blocked
  state still comes from Herdr's screen detection. After a Herdr upgrade, an "update" banner that
  survives `herdr server stop` usually means this hook is outdated, not the binary: check with
  `herdr integration status` and rerun the install command. `herdr status` shows
  `server_binary_stale` for the binary case.
- **First apply on a machine where Herdr already ran**: onboarding writes a plain
  `~/.config/herdr/config.toml`, and mise refuses to replace a real file with a link. Delete that
  file, then `mise dot apply`.
- **Herdr worktrees and the bare-repo layout.** Repos live as `~/code/<repo>/.bare` plus sibling
  checkouts. Open `~/code/<repo>` itself (the folder holding `.bare`) as the workspace: that is the
  repo's **parent** row, the only place New worktree and Open worktree work (`worktree create`
  from a checkout fails with `linked_worktree_source`). Checkouts group under it as children.
  Herdr resolves the repo name from the common git dir, so `[worktrees] directory = "~/code"`
  creates `~/code/<repo>/<branch-slug>`, the same sibling layout. Delete worktree checkout in the
  sidebar runs `git worktree remove`; it never deletes the branch. The parent row's branch line
  shows the bare repo's `HEAD`; keep it pointed at the default branch
  (`git -C ~/code/<repo> symbolic-ref HEAD refs/heads/master`).
- **Linear** launches `linear-work` with almost no PATH and no TTY; the script adds the mise shims
  itself. It requires a working-directory preselected on the issue (`LINEAR_WORK_DIR`) and a
  running Herdr server; it notifies via Notification Center and exits otherwise.
- **`hx-open`** uses `herdr pane run`, so quitting Helix leaves a shell in that tab.
- **Coder**: `install.sh` is the first script name `coder dotfiles` looks for. Casks other than
  fonts skip on Linux automatically. GitHub-release downloads can hit API rate limits on shared
  boxes; set `MISE_GITHUB_TOKEN` in `~/.localenv` there.
